# راه‌اندازی پی‌پینگ برای ختم‌ساز

اتصال نرم‌افزاری پی‌پینگ نسخهٔ ۳ در پروژه آماده است. برای فعال‌شدن پرداخت
واقعی فقط توکن اختصاصی API و آدرس HTTPS عمومی لازم است.

## چه چیزی را کجا ذخیره کنم؟

نام کاربری و رمز پنل را داخل پروژه، `.env`، سورس کد یا تلگرام ذخیره نکنید.
این دو فقط برای ورود به پنل پی‌پینگ‌اند و بهتر است در Password Manager شخصی
نگهداری شوند.

بعد از ساخت «توکن اختصاصی» در بخش توسعه‌دهندگان پی‌پینگ، فایل `.env` در ریشهٔ
پروژه را باز کنید و فقط این دو مقدار را قرار دهید:

```dotenv
PAYPING_API_TOKEN=توکن_اختصاصی_ساخته_شده_در_پنل
PAYPING_CALLBACK_URL=https://khatmsaz.com/payments/payping/callback
```

نام متغیرها باید دقیقاً همین باشد. توکن را داخل گیومه نگذارید و آن را commit
یا برای دیگران ارسال نکنید. توکن نشست مرورگر یا متن داخل URL ورود، توکن API
پروژه نیست و نباید در `.env` قرار بگیرد.

## پیش‌نیاز دامنه

دامنهٔ `khatmsaz.com` باید به سروری اشاره کند که برنامه روی آن اجرا می‌شود،
گواهی معتبر HTTPS داشته باشد، و reverse proxy مسیر زیر را به FastAPI برساند:

```text
POST /payments/payping/callback
```

آدرس محلی مثل `192.168.x.x` برای callback بانکی مناسب نیست. قبل از بازکردن
هزینهٔ ساخت ختم، یک پرداخت واقعی کم‌مبلغ انجام دهید و موفقیت آن را با
`/wallet` کنترل کنید.

## کاربر چه دستوری بزند؟

- `/start` بات را برای کاربر شروع می‌کند.
- `/wallet` موجودی و چهار دکمهٔ سادهٔ شارژ را نشان می‌دهد.
- `/topup` همان صفحهٔ سادهٔ شارژ را مستقیم باز می‌کند.
- `/invoices` آخرین فاکتورها، رسیدهای شارژ و بازپرداخت‌ها را نشان می‌دهد.
- اگر ساخت ختم پولی باشد و کاربر کد داشته باشد، در صفحهٔ تأیید
  `/coupon CODE` را می‌فرستد؛ نداشتن کد هیچ مرحلهٔ اضافه‌ای ایجاد نمی‌کند.

مدیر ارشد در پنل وب از بخش «مالی» می‌تواند جمع مبالغ، آخرین فاکتورها و
کدهای تخفیف را ببیند و کد جدید بسازد یا فعال/غیرفعال کند.

کاربر مبلغ را لمس می‌کند، دکمهٔ پرداخت امن را می‌زند، پرداخت بانکی را کامل
می‌کند و پس از پیام «کیف پول شارژ شد» به بات برمی‌گردد. callback تکراری باعث
شارژ دوباره نمی‌شود.

## نام‌گذاری فایل‌های قرآن، اگر نسخهٔ فایل محلی هم نگهداری شد

بات فعلی مستقیماً از شناسهٔ پیام‌های کانال خصوصی استفاده می‌کند و برای کار
روزمره نیازی به تغییر نام فایل‌های کانال نیست. برای آرشیو محلی منظم، این
الگوها را استفاده کنید:

```text
quran_madina_hafs_page_001.jpg
quran_madina_hafs_page_002.jpg
...
quran_madina_hafs_page_604.jpg

quran_parhizgar_pages_001-002.mp3
quran_parhizgar_pages_003-004.mp3
quran_parhizgar_pages_005-007.mp3
```

برای تصویر همیشه شمارهٔ سه‌رقمی همان صفحه را بنویسید. برای صوت، شمارهٔ اولین
و آخرین صفحهٔ واقعی داخل همان فایل را بنویسید؛ بنابراین فایل دوصفحه‌ای
`001-002` و فایل سه‌صفحه‌ای `005-007` است. لازم نیست فرض کنیم همهٔ صوت‌ها
دقیقاً دو صفحه‌اند. قاری در کد با شناسهٔ ثابت `parhizgar` و عنوان «شهریار
پرهیزگار» ثبت شده است.

## نکتهٔ مهم دربارهٔ محصول و توکن

برای این پروژه «لینک ارجاع محصول» جای توکن API یا Callback را نمی‌گیرد.
کد، درخواست پرداخت را با فاکتور داخلی و `clientRefId` خودش می‌سازد و بعد از
بازگشت، مبلغ و فاکتور را در Callback بررسی می‌کند. بنابراین در پنل پی‌پینگ
محصولی با URL مستقل لازم نیست بسازید؛ چیزی که باید دستی تهیه شود فقط
توکن اختصاصی API است. نمونهٔ رسمی پی‌پینگ نیز پرداخت را با Bearer token و
`clientRefId` نشان می‌دهد:

https://github.com/payping/PHP-Basic-Example-Payment/blob/master/payment.php
