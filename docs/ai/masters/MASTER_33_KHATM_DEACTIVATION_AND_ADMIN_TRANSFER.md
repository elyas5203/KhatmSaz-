# MASTER-33: سیستم واگذاری مدیریت ختم به پشتیبانی و غیرفعال‌سازی عضوگیری جدید (بند ۵ قوانین)

## ۱. چرایی و فلسفه معماری (Context & Rule 5 Mandate)

مطابق بند ۵ از قوانین رسمی ساخت و مدیریت ختم در ختم‌ساز:
> «در صورتی که سازنده ختم بخواهد ختم خود را غیر فعال کند و توان مدیریت ختم را نداشته باشد، لازم است درخواست خود را به صورت کتبی به پشتیبانی خدمتگزاران تک ارسال نماید و طبیعی است بعد از بسته شدن لینک ختم، مدیریت ختم به مجموعه خدمتگزاران تک منتقل می‌گردد و اعضای قبلی می‌توانند به ختم خود ادامه دهند.»

پیش از این، سازنده فقط گزینه «لغو ختم» (Cancel Khatm) را داشت که در صورت وجود عضو فعال با خطای «به دلیل عضویت اعضا امکان لغو وجود ندارد» مسدود می‌شد؛ زیرا حذف ختم منجر به پایمال شدن سهم‌ها و توقف ختم اعضای وفادار می‌گردید.

در این مستند، سامانه کامل **واگذاری مدیریت (Khatm Delegation & Deactivation)** پیاده‌سازی شده است تا سازنده بتواند به شکل کاملاً استاندارد و با نظارت پشتیبانی، مدیریت را به خدمتگزاران تک واگذار نموده و لینک عضوگیری جدید مسدود گردد، در حالی که اعضای فعلی حتی یک روز نیز از قرائت باز نمانند.

همچنین در این نسخه، دکمه و بنرهای آزمایشی «سفارش ساخت ویدیو» که به اشتباه از یک تسک نامربوط وارد شده بود، به دستور صریح کارفرما به‌صورت کامل از ربات و وب پاکسازی گردید.

## ۲. مدل داده و پایگاه داده (Data Model)

فیلدهای الحاقی به جدول `khatms`:
```sql
ALTER TABLE khatms ADD COLUMN IF NOT EXISTS join_link_closed BOOLEAN DEFAULT FALSE;
ALTER TABLE khatms ADD COLUMN IF NOT EXISTS transfer_request_status VARCHAR(20) DEFAULT 'NONE';
ALTER TABLE khatms ADD COLUMN IF NOT EXISTS transfer_request_reason VARCHAR(500);
ALTER TABLE khatms ADD COLUMN IF NOT EXISTS transfer_requested_at TIMESTAMP WITH TIME ZONE;
ALTER TABLE khatms ADD COLUMN IF NOT EXISTS transferred_to_admin_at TIMESTAMP WITH TIME ZONE;
ALTER TABLE khatms ADD COLUMN IF NOT EXISTS transferred_from_user_id UUID REFERENCES users(id);
CREATE INDEX IF NOT EXISTS ix_khatms_transfer_status ON khatms(transfer_request_status);
```

### مقادیر وضعیت واگذاری (`transfer_request_status`):
- `NONE`: حالت عادی، هیچ درخواستی ثبت نشده است.
- `PENDING`: سازنده درخواست واگذاری را ثبت کرده و منتظر بررسی ادمین در `@khatmsaz_admin_bot` یا پنل وب است.
- `APPROVED`: درخواست توسط ادمین تأیید شده است. فیلد `join_link_closed = True` گردیده و `creator_user_id` به کاربر ادمین سامانه (خدمتگزاران تک) منتقل شده است.
- `REJECTED`: درخواست توسط ادمین رد شده است و سازنده مطلع گردیده است.

## ۳. جریان کاربری در ربات سازنده (Creator Bot Experience)

۱. **منوی ختم‌های من (`my_khatms`):**
   - در کیبورد مدیریت هر ختم فعال (`creator_khatm_keyboard`):
     - اگر وضعیت `NONE` یا `REJECTED` باشد: دکمه `[🤝 واگذاری مدیریت به پشتیبانی]` با کالبک `khatm_transfer_ask:{id}` نمایش داده می‌شود.
     - اگر وضعیت `PENDING` باشد: دکمه `[⏳ لغو درخواست واگذاری]` با کالبک `khatm_transfer_cancel:{id}` نمایش می‌یابد.
     - اگر وضعیت `APPROVED` باشد: برچسب «مدیریت به خدمتگزاران تک واگذار شده است» نشان داده می‌شود.

۲. **دیالوگ تأیید بند ۵ قوانین:**
   - پس از زدن دکمه واگذاری، متنی شفاف با ذکر بند ۵ نمایش داده می‌شود:
     - توضیح بسته شدن لینک عضوگیری جدید.
     - تضمین استمرار ختم برای اعضای فعلی بدون توقف.
     - انتقال مدیریت به مجموعه خدمتگزاران تک.
   - دکمه‌های [✅ تأیید و ارسال به پشتیبانی] و [🔙 انصراف].

۳. **ثبت و ارسال به ادمین:**
   - وضعیت ختم به `PENDING` تغییر می‌یابد.
   - نوتیفیکیشن فوری به ادمین‌ها در ربات `@khatmsaz_admin_bot` فرستاده می‌شود.

## ۴. جریان نظارت و تأیید ادمین (Admin Bot & Web Approval)

۱. **ربات ادمین (`@khatmsaz_admin_bot`):**
   - پیام پوش آنی شامل: عنوان ختم، شناسه، نام و شناسه سازنده، تعداد اعضای فعال، زمان درخواست و دلیل.
   - دکمه‌های شیشه‌ای:
     - `[✅ تأیید واگذاری و بستن لینک]` (`admin_transfer:approve:{id}`)
     - `[❌ رد درخواست]` (`admin_transfer:reject:{id}`)
   - پیشخوان ادمین: نمایش تعداد در بخش `[🤝 واگذاری مدیریت ({n})]` (`admin:transfers`).

۲. **عملیات پس از تأیید ادمین:**
   - `join_link_closed = True`
   - `transfer_request_status = "APPROVED"`
   - `transferred_to_admin_at = now()`
   - `transferred_from_user_id = khatm.creator_user_id`
   - `khatm.creator_user_id = admin_user.id`
   - ارسال پیام به سازنده قبلی در تلگرام و بله مبنی بر تأیید واگذاری و تداوم تلاوت اعضا.

۳. **پنل وب ادمین (`/khatms/{id}`):**
   - امکان بررسی و تأیید/رد با یک کلیک.

## ۵. رفتار لینک عضویت برای اعضا (Member Join Gate)

در `member_start.py` (ورود با دیپ‌لینک `join_{token}`):
- اگر `join_link_closed == True`:
  - بررسی می‌شود که آیا این کاربر قبلاً عضو این ختم بوده است یا خیر.
  - **اگر قبلاً عضو بوده:** بدون مانع وارد منوی ختم و سهم‌های خود می‌شود.
  - **اگر عضو نبوده:** پیامی صمیمانه نمایش داده می‌شود:
    > «⚠️ **امکان عضویت جدید در این ختم وجود ندارد**  
    > لینک عضویت این ختم توسط مدیریت بسته شده و اعضای قبلی در حال تکمیل قرائت هستند.  
    > جهت شرکت در سایر ختم‌ها می‌توانید از منوی ربات اقدام فرمایید.»

---

## ۶. پنل وب سازنده (Creator Web Panel)

در صفحه `/creator/khatms/{id}`:
- حذف کامل بنر سفارش ساخت ویدیو.
- افزودن کارت واگذاری مدیریت ختم با توجه به وضعیت جاری (`NONE`، `PENDING`، `APPROVED`).
- مسیرهای وب امن با CSRF:
  - `POST /creator/khatms/{id}/transfer/request`
  - `POST /creator/khatms/{id}/transfer/cancel`
