# GOAL — بازطراحی کامل پنل ادمین و پنل سازنده (۲۰۲۶-۰۹-۲۹)

> نویسنده: Claude Code — بر اساس درخواست مستقیم مالک پروژه + بررسی گراف
> `graphify-out/` و کد فعلی. این سند «چه چیزی و چرا» است؛ پیشرفت واقعی در
> `PROJECT_STATE.md` ثبت می‌شود.

## خواستهٔ مالک (نقل مستقیم، خلاصه‌شده)

1. پنل **ادمین** و پنل **سازنده (creator)** را کامل از نو بساز — این دو
   شخصیت متفاوت‌اند و پنل‌هاشان باید فرق داشته باشد.
2. UI/UX خیلی خوب و مدرن، با استفاده از اسکیل‌های طراحی.
3. **اولویت شمارهٔ یک: سادگی، دسترسی‌پذیری، و دسترسی فوق‌آسان به اطلاعات.**
4. اطلاعات باید **دسته‌بندی‌شده، والد/فرزند (parent/child)، و لید (خلاصه‌دار)**
   باشد — نه یک لیست بلند.
5. **هر امکانی که در بات هست، باید در پنل همان شخصیت هم در دسترس باشد** —
   پشتیبانی کامل از همه‌چیز.
6. در منوی بات ختم‌ساز (مخصوص سازنده‌ها) یک دکمهٔ **«شارژ کیف پول»** اضافه شود
   (الان سازنده‌ها این دکمه را ندارند، هرچند فلوی شارژ از قبل وجود دارد).
7. بعد از تغییرات: گراف را به‌روز کن، کامیت و پوش کن تا مالک از GitHub روی سرور
   بکشد.

## وضعیت فعلی (یافته‌های بررسی)

سه سطح رابط کاربری وجود دارد:

- **پنل وب Mini App ادمین** (`web/app.py` + `templates/base.html` و صفحات):
  نسبتاً کامل — داشبورد، ختم‌ها، کاربران، احراز شماره، پیام گروهی، مالی/پلن،
  دسته‌ها، دعاها، پیام‌ها، باتها، سلامت، رویدادها، مدیران. طراحی glassmorphism
  با sidebar دسکتاپ + dock موبایل.
  - **شکاف واقعی:** تأیید درخواست سازندگان از وب وجود ندارد؛ پنل اینلاین بات
    می‌گوید «از دیتابیس اقدام کنید» (`panel.py:145`). این باید در پنل وب بیاید.
  - داشبورد KPI/میان‌بر منسجم ندارد؛ ناوبری گروه‌بندی‌شده ولی بدون صفحهٔ خانهٔ
    «دسترسی سریع».

- **پنل وب Mini App سازنده** (`/creator`, `creator_base.html`,
  `creator_dashboard.html`, `creator_khatm_detail.html`): **بسیار لاغر** —
  فقط لیست ختم‌ها + صفحهٔ جزئیات هر ختم (اعضا، اکسل، تنظیمات). هیچ داشبورد
  خلاصه، کیف پول، پلن، پیام گروهی، دعوت/QR، یا ناوبری بخش‌بندی‌شده ندارد.
  → بزرگ‌ترین شکاف. سازنده در بات این‌ها را دارد ولی در پنل وب نه.

- **منوهای reply بات** (`keyboards.py`): سازنده = ساخت ختم / مدیریت / مالی /
  تنظیمات / پشتیبانی. `creator_finance_keyboard` فقط «گزارش» دارد و کامنت
  `# Add wallet button later if needed` (خط ۱۵۴). فلوی کامل کیف پول
  (`handlers/wallet.py`: `/wallet`, `/topup`, `wallet:open`, مبالغ شارژ،
  PayPing) از قبل ساخته و روی `dp_creator` رجیستر شده — فقط دکمه ندارد.

- **پنل اینلاین بات** (`panel.py`): «🎛 پنل مدیریت» سازنده/ادمین — چند دکمهٔ
  میان‌بر که به فلوهای واقعی وصل‌اند، به‌جز چند بن‌بست ادمین (creator_requests,
  users, broadcast) که به «از دیتابیس/اسکریپت اقدام کن» ختم می‌شوند.

## اهداف این کار (Definition of Done)

### A) دکمهٔ شارژ کیف پول سازنده (کوچک، سریع، مستقل)
- «💳 شارژ کیف پول» به `creator_finance_keyboard` و به پنل اینلاین سازنده
  (`creator_panel_keyboard`) اضافه شود و به `_show_wallet` وصل شود.
- کلید i18n `menu.creator.wallet` (fa/ar/en). هندلر متن دکمه.
- تست: دکمه ↔ هندلر ↔ import.

### B) بازطراحی پنل وب سازنده (بزرگ‌ترین بخش)
یک پنل کامل با ناوبری بخش‌بندی‌شده (dock موبایل + sidebar دسکتاپ مثل ادمین):
1. **خانه/داشبورد**: کارت‌های KPI (تعداد ختم فعال، کل اعضا، موجودی کیف پول،
   پلن فعلی) + میان‌بُرهای «ساخت ختم / پیام گروهی / شارژ کیف پول».
2. **ختم‌های من**: نمای **والد/فرزند** — سطح ۱: فعال / تمام‌شده؛ سطح ۲: بر اساس
   نوع (قرآن/صلوات/دعا/لعن)؛ لید هر ختم (عنوان، وضعیت، تعداد عضو). دقیقاً الگوی
   سلسله‌مراتبی خواستهٔ مالک (BACKLOG #18).
3. **کیف پول و مالی**: موجودی + اعتبار + پلن، تاریخچهٔ فاکتورها، و لینک‌های شارژ
   (هم‌راستا با فلوی PayPing بات؛ در وب فقط نمایش + راهنمای شارژ از بات، چون
   پرداخت داخل بات امن‌تر است — یا لینک شارژ اگر امکان‌پذیر بود).
4. **جزئیات ختم** (بازطراحی `creator_khatm_detail.html`): همهٔ اکشن‌های سازنده
   یک‌جا و دسته‌بندی‌شده — آمار، لیست اعضا (جستجو/صفحه‌بندی)، خروجی اکسل،
   لینک/QR دعوت، تنظیمات، پیام گروهی این ختم.
- همه چندزبانه (fa/ar/en) با `t()`؛ RTL/LTR درست.

### C) بازطراحی/تکمیل پنل وب ادمین
1. **داشبورد خانه**: بازطراحی به «مرکز فرماندهی» با KPIهای واقعی و کارت‌های
   دسترسی سریع گروه‌بندی‌شده (محتوا / کاربران‌وختم‌ها / مالی / سیستم / مدیریت).
2. **تأیید سازندگان از وب**: صفحه/بخش جدید برای دیدن و تأیید/رد
   `creator_requests` (رفع بن‌بست فعلی که به دیتابیس ارجاع می‌دهد).
3. یکدست‌سازی ظاهر همهٔ صفحات با سیستم طراحی مشترک (کارت‌ها، سرصفحه، لید).

### D) پنل اینلاین بات
- بن‌بست‌های ادمین (`admin_panel:creator_requests`, `:users`, `:broadcast`)
  به صفحات واقعی پنل وب اشاره کنند، نه «از دیتابیس اقدام کن».
- دکمهٔ شارژ کیف پول در پنل اینلاین سازنده (بخش A).

## اصول طراحی (از اسکیل‌های طراحی + قوانین پروژه)
- سادگی و لمس‌پذیری اول؛ متن فارسی گرم و ساده (قانون CLAUDE.md / TONE_GUIDE).
- سیستم طراحی موجود (Vazirmatn، glass-card/panel، امرالد/تیل، dock موبایل)
  حفظ و منسجم شود — نه یک تم کاملاً جدید که ناسازگاری بیاورد.
- والد/فرزند و لید همه‌جا؛ هیچ لیست بلند بدون گروه‌بندی.
- بدون اختراع قانون کسب‌وکاری جدید (CLAUDE.md). فقط نمایش/دسترسی به امکاناتِ
  موجود.
